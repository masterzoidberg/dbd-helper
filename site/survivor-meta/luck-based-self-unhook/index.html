Original Research Article

C13 — Luck-Based Self-Unhook

Identity

  • Strategy ID: C13
  • Name: Luck-Based Self-Unhook
  • Alternative Names: Kobe build, luck build, old Slippery Meat
  • Structural Classification: NICHE STRATEGY
  • Current Status: LEGACY
  • Parent Strategy: None
  • Patch Baseline: 10.2.0
  • Solo Q: Not Current
  • Coordinated SWF: Not Current
  • Meta Stability: Not Current
  • Trend: Not Current
  • Prevalence: Rare

Short Description

A preserved historical strategy identity: Retained because “luck/Kobe build” remains recognizable terminology. It remains in the encyclopedia so older guides and community terminology still resolve to the correct modern context.

What It Was

Historically used luck-based self-unhook attempts. Stage 2 treats the classic luck strategy as invalidated/legacy; deterministic self-unhook (C12) is the current replacement family.

Why It Mattered

Players used it because historical self-unhook identity. Its value came from a specific interaction or strategic pattern that was coherent enough to deserve its own identity at the time.

What Changed

No material 10.2-specific change was established for the persistent strategic concept; current evaluation is carried forward from Stage 2.

Why It Is Not Current

The canonical snapshot uses LEGACY / NOT_CURRENT, not D tier. A D-tier label would imply the old strategy still exists as a current low-power choice. Here, the relevant conclusion is that the historical interaction or plan has been invalidated or superseded.

Current Successor

[C12 — Deterministic Self-Unhook]

Perks and Historical Build Structure

Core / Defining Tools

Historically Slippery Meat + luck effects

Supporting Tools

Supporting slots should protect the strategy's activation, reduce its opportunity cost, or cover a failure state rather than simply duplicate the same effect.

Flex Options

A flex slot can change without changing strategy identity as long as the core gameplay loop remains intact.

Trap / Outdated Choices

The main trap is overinvestment: adding more same-purpose perks can turn a useful module into dead slots when the Killer or match state refuses the interaction.

Common Mistakes
